# Python — Автоматический рабочий процесс

## КОГДА ПРИМЕНЯТЬ
Каждый раз, когда пользователь даёт **Python-задачу** — выполнять ВСЕ четыре шага по порядку, без дополнительных уточнений.

---

## ШАГ 1 — ПРОЕКТИРОВАНИЕ (таблицы ДО кода)

Прочитать все файлы: PYTHON_ИНСТРУКЦИЯ.md → PYTHON_СТИЛЬ.md → PYTHON_СТРУКТУРА.md → PYTHON_АНТИПАТТЕРНЫ.md

Затем показать:

**Выбор шаблона:**
Шаблон А (Скрипт) / Б (ООП) / В (API) / Г (Data Pipeline) / Д (Automation) — и почему.

**Таблица 2.1 — Компоненты** (что будет в коде: классы, функции, их роли)
**Таблица 2.2 — Зависимости** (все импорты + версии, до написания)
**Таблица 2.3 — Сигнатуры** (полные type hints сигнатуры всех функций)

---

## ШАГ 2 — НАПИСАНИЕ КОДА

Написать код строго по:
- PYTHON_СТИЛЬ.md (именование, type hints, docstrings, структура модуля)
- Выбранному шаблону из PYTHON_СТРУКТУРА.md
- Правилам безопасности из PYTHON_АНТИПАТТЕРНЫ.md §3

КРИТИЧНО: копировать сигнатуры и импорты из таблиц — не изобретать заново.

---

## ШАГ 3 — ВЕРИФИКАЦИЯ

Проверить код через таблицы:

**Таблица 3.1 — Безопасность** (SQL injection, секреты, eval, pickle)
**Таблица 3.2 — Исключения** (нет голых except:)
**Таблица 3.3 — Сложность** (нет O(n²) без обоснования)
**Таблица 3.4 — Чеклист качества** (типы, docstrings, DRY, SRP)
**Сводная таблица АНТИПАТТЕРНЫ.md §4** (сканирование ошибок ИИ)

Показать результаты проверки.

### Формат вывода шагов 1–3:
```
## ВЫБОР ШАБЛОНА
[Шаблон X — почему]

## ТАБЛИЦЫ ДО НАПИСАНИЯ
[Таблицы 2.1, 2.2, 2.3]

## КОД
[Полный код]

## ВЕРИФИКАЦИЯ
[Таблицы 3.1–3.4 + антипаттерны]

## СТАТУС
✅ Код готов к использованию
ИЛИ
❌ Найдены проблемы: [список]
```

---

## ШАГ 4 — ИСПРАВЛЕНИЕ (если найдены проблемы в шаге 3)

Если в верификации ❌ — сразу исправить.

```
## АНАЛИЗ ПРОБЛЕМ
[Для каждой: что нарушено, почему возникло]

## ИСПРАВЛЕННЫЙ КОД
[Полный код]

## ПОВТОРНАЯ ВЕРИФИКАЦИЯ
[Результаты]

## СТАТУС
✅ Все проблемы исправлены
ИЛИ
❌ Остались проблемы: [список]
```
